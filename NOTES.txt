Configuration means defining common settings and constants of the system.

1.4 PAGE_SIZE
PAGE_SIZE = 4096
PAGE_SIZE defines the size of one database page.
MyRDB uses 4096 bytes (4 KB) fixed-size pages.
Database files are divided into these pages.
Fixed-size pages make disk storage and page addressing easier.
The storage engine will use this value while reading and writing pages.

Example:

Database File
│
├── Page 0 → 4096 bytes
├── Page 1 → 4096 bytes
├── Page 2 → 4096 bytes
└── Page 3 → 4096 bytes

1.5 PAGE_MAGIC
PAGE_MAGIC = b"MYDB"
PAGE_MAGIC is a special sequence of bytes used to identify the MyRDB format.
It helps the engine check whether a page/file belongs to MyRDB.
It is stored in the page/file header.
It helps detect invalid or incompatible files.
It is not a security feature.

Basic checking:

Read Page
   ↓
Check Magic
   ↓
MYDB?
 /   \
Yes   No
 ↓     ↓
Valid  Error
Easy way to remember:

PAGE_MAGIC = "Is this a MyRDB page?"
--------------------------------------------------------------------------------------------------------


1.6 FORMAT_VERSION
FORMAT_VERSION = 1
FORMAT_VERSION identifies the version of MyRDB's binary storage format.
It helps the engine understand how the stored data is structured.
The format can change in future versions.
Version checking prevents the engine from incorrectly reading an incompatible database file.

Example:

MYDB + Version 1 → Current MyRDB format
MYDB + Version 2 → Future format
Easy way to remember:

PAGE_MAGIC → Which format?

FORMAT_VERSION → Which version of that format?

2.5 Page Header Binary Layout

Page Header is the metadata stored at the beginning of every database page.

In MyRDB, the Page Header contains:

Field	Size	Purpose
Magic	4 bytes	Identifies a valid MyRDB page
Version	2 bytes	Identifies storage format version
Page ID	4 bytes	Identifies the page
Record Count	2 bytes	Number of records in the page
Free Space	4 bytes	Available free space in the page

Total Header Size = 4 + 2 + 4 + 2 + 4 = 16 bytes

Binary Layout
Byte 0–3     → Magic
Byte 4–5     → Version
Byte 6–9     → Page ID
Byte 10–11   → Record Count
Byte 12–15   → Free Space

Since MyRDB uses a 4096-byte page:

4096 - 16 = 4080 bytes

So, 4080 bytes remain for record data, free space, and slot directory.
-------------------------------------------------------------------------------------------------------------------

2.6 Field Sizes & Struct Format

Python struct is used to convert Python values into a fixed binary format for storage.

Struct Format Codes
Code	Meaning	Size
4s	4-byte bytes field	4 B
H	Unsigned short integer	2 B
I	Unsigned integer	4 B

Therefore, MyRDB's Page Header format is:

4s H I H I

Combined:

"4sHIHI"
Meaning
4s → Magic
H  → Version
I  → Page ID
H  → Record Count
I  → Free Space

Example:

struct.pack("4sHIHI",
            b"MYDB",
            1,
            5,
            3,
            2000)

This converts:

Magic        = MYDB
Version      = 1
Page ID      = 5
Record Count = 3
Free Space   = 2000

into binary bytes.

Important
struct.pack() → Python values → bytes
struct.unpack() → bytes → Python values
struct only performs conversion.
File operations such as read() and write() actually access the .db file.

2.7 — Byte Order / Endianness
New Concept

Endianness means the order in which multiple bytes of a value are stored in memory or in a binary file.

Jab hum struct se Page ID, Version, Free Space jaise numbers ko bytes mein convert karenge, toh decide karna padega ki bytes kis order mein store honge.

There are two common byte orders:

1. Little-Endian

The least significant byte is stored first.

Example:

Number = 0x12345678

Little-Endian:
78 56 34 12
2. Big-Endian

The most significant byte is stored first.

Number = 0x12345678

Big-Endian:
12 34 56 78
Why do we need it in MyRDB?

MyRDB stores pages as binary data.

If we don't explicitly define the byte order, 
the same database file could potentially be interpreted differently on different systems.

So MyRDB should have a fixed binary format.

For our project, we'll use Little-Endian.

2.9 Page Creation & Initialization
Page Initialization means preparing a new empty page for database use.
MyRDB will create pages of fixed size 4096 bytes.
Every new page will have a Page Header.
Initial record_count will be 0.
The page will initially contain no records.
page_id will uniquely identify the page.

The remaining space will be available for records and the slot directory.
Page initialization prepares the page before records are inserted.

2.10 Page Read / Write

File I/O means reading data from and writing data to a file.
MyRDB will use file operations to access .db files.
write() stores page bytes in the database file.
read() retrieves page bytes from the database file.
seek() moves to a specific position in the file.
Each page has a fixed size of 4096 bytes.

The location of a page can be calculated using:
Page Offset = Page ID × PAGE_SIZE
Example:
Page ID = 2
Page Size = 4096
Offset = 2 × 4096 = 8192 bytes
Flow
Page ID
   ↓
Calculate Offset
   ↓
seek()
   ↓
read() / write()
   ↓
Database File
Important
struct → converts Python values ↔ bytes.
File I/O → transfers bytes ↔ disk file.
